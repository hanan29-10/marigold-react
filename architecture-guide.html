Developer learning guide

MORON website architecture

This document explains the current project. It does not run or change the shop.

1. The big idea

MORON is a Vite + vanilla JavaScript single-page application. index.html contains an empty #app element. src/main.js chooses a page from the URL hash and inserts that page into #app.

index.html → src/main.js → header + selected page + footer → #app in the browser products.js → products module → productCard() → product cards cart.js → storage.js → browser Local Storage

2. Loading the homepage

  1. The browser opens index.html.
  2. It loads /src/main.js as a JavaScript module.
  3. main.js imports CSS, data, pages, components, and logic modules.
  4. If there is no hash, it sets the URL to #/.
  5. renderRoute() calls homePage().
  6. renderLayout() inserts the header, home content, and footer into #app.
  7. renderCatalog() inserts the selectable product cards.
  8. startCarousel() activates the hero slides.

3. Folder responsibilities

Location Responsibility
src/data Static product information and categories.
src/components Reusable user-interface pieces: header, footer, hero, and product card.
src/pages Complete page templates: home, product detail, cart, and checkout.
src/modules Reusable logic: cart, storage, validation, filtering, search, sorting, and catalog creation.
src/styles Global visual and mobile-first responsive styles.
public Files available directly by URL, such as /images/moron-sienna-tote.png.

4. Routing

The website uses hash routing rather than a routing library.

#/                         → homepage
#/shop                    → homepage, then the shop section
#/product/sienna-tote     → product details
#/cart                    → cart page
#/checkout                → checkout page

In main.js, location.hash is split into a page name and, when needed, a product id. The hashchange event runs renderRoute() whenever navigation changes.

5. Product data reaches the screen

src/data/products.js exports a products array. Each object has values such as id, name, category, price, image, and description. 

products.js
  → getCatalog() in modules/products.js
  → productCard(product) in components/productCard.js
  → HTML placed in .catalog .product-grid

The product id also powers detail links such as #/product/sienna-tote and add-to-cart buttons such as data-add="sienna-tote".

6. Search, filter, and sort

home.js keeps the current choices in catalogState. 

{ category: 'All', term: '', sort: 'featured' }

getCatalog() composes small modules in this order:

filterByCategory(products, category) → searchProducts(products, term) → sortProducts(products, order) → cards shown in the catalog

7. Cart and Local Storage

modules/cart.js owns the active cart. It loads it when the app starts, updates quantities, calculates totals, and asks modules/storage.js to save it. 

addToCart(product)
  → saveCart(cart)
  → localStorage['shopboard-cart'] = JSON text
  → dispatch 'cart:updated'
  → refreshCartCount() updates the header

This is why the bag remains after a browser refresh. Checkout is simulated: valid form submission clears the cart and shows a confirmation; it does not process a payment.

8. Import and export

JavaScript files share code through ES modules. For example, products.js exports products, and modules/products.js imports it. This keeps source data separate from the functions that search and display it. 

// products.js
export const products = [...];

// modules/products.js
import { products } from '../data/products.js';

9. Main files and what happens if they disappear

File Purpose Without it
index.html Browser entry document and #app mount point. The app cannot start.
src/main.js Application controller, routing, layout, and event listeners. The page stays empty.
data/products.js Product records and categories. No catalog or product details.
pages/*.js HTML templates for complete screens. The related route fails.
components/*.js Reusable page pieces. Any importer of that component fails.
modules/*.js Focused reusable business logic. The related feature fails.
styles/main.css Appearance and responsive layout. The app works but is largely unstyled.
public/images/* Product and campaign visuals. The related image does not load.

10. Where to add features

  • Add a product: src/data/products.js.
  • Add a new full page: create a file in src/pages, then add a case to renderRoute() in src/main.js.
  • Add reusable visual markup: src/components.
  • Add feature logic such as a wishlist: create a focused file in src/modules.
  • Add persistent browser data: follow the storage.js pattern.
  • Add styling: src/styles/main.css, beginning with mobile styles and extending with min-width media queries.
